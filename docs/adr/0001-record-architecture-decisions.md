# 1. Record architecture decisions

Date: 2026-08-28

## Status

Accepted

## Context

This is a learning + portfolio project. Reviewers (and future me) benefit from
seeing *why* choices were made, not just the code.

## Decision

Keep short ADRs in `docs/adr/`, numbered, in the format popularised by Michael
Nygard: Context, Decision, Consequences. One file per decision. Never edit an
accepted ADR's decision — supersede it with a new one.

## Consequences

- Small ongoing writing cost.
- A clear trail for interviews ("walk me through a tradeoff you made").
